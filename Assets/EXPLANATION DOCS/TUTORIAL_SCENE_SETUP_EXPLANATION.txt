TUTORIAL.UNITY - IMPLEMENTED INSPECTOR AND CONTENT SETUP
========================================================

Where the controller is attached
--------------------------------
SortingTutorialController is attached to the existing Board GameObject. This keeps
the four current sorting-Tutorial references in one visible place without adding a
new scene hierarchy object.

Registration values
-------------------
Tutorial ID: sorting.initial
Required Level: 0
Priority: 100
Auto Start: enabled
Repeat Behavior: Once
Force Start In Development: disabled

The ID is the stable persistence and restart-reset key. Required Level zero allows
the initial Tutorial to run before normal level numbering matters.

Sorting controller references
-----------------------------
Board
    Existing Board component on the same GameObject.

Spawn Controller
    Existing SpawnContoller on SpawnMamager.

Hand Animation
    Existing HandAnimation on the Board GameObject.

Tool Tip Tutorial
    Existing ToolTipTutorial on the Board GameObject.

All references are direct serialized scene references. Runtime name searches are
not used for core Tutorial flow.

Adaptive destination settings
-----------------------------
Direction Priority:
    1. Right
    2. Left
    3. Down
    4. Up

Destination Retry Delay: 0.25 seconds

Designers can reorder the list in the Inspector without editing code. Board still
makes the final validity decision for each candidate.

Stage 2 ordered input behavior
------------------------------
The three spawned Boxes are consumed from the visible left side of the rail to the
right: left, middle, then right. SortingTutorialController sorts the returned Box
references by final world X and installs a temporary owner-scoped drag predicate on
each one. Only the Box currently indicated by the Hand can enter its drag lifecycle.

Trying the middle or right Box early should have no visible effect: its Transform
must not move, DragStarted must not fire, and the Hand/prompt should remain on the
current instruction. After the left Box is accepted and Board finishes resolving,
the middle Box unlocks. The right Box unlocks only after the middle Box completes.

This is runtime controller behavior rather than another Inspector checkbox. It is
specific to configured stage index 1, which is the current two-color phase.

Restart button now resets only this Tutorial and loads TUTORIAL with exact casing.

TutorialManager Editor-testing object
-------------------------------------
TUTORIAL contains a root GameObject named TutorialManager with the central
TutorialManager component. Its Editor Testing values are:

Editor Testing Tutorial ID: sorting.initial
Force Tutorial In Editor: enabled

The normal runtime bootstrap still creates the persistent singleton before scene
load. During Editor Play Mode, the scene component copies these two test values to
that singleton and then removes only its own duplicate GameObject. This makes the
checkbox editable and saved in TUTORIAL.unity without producing two active
managers, two evaluations, or duplicated event subscriptions.

The component's Reset Tutorial Progress context command deletes only the
sorting.initial completion value through the shared completion store. The force
checkbox itself will never delete or overwrite saved progress.

Completion panel and navigation
-------------------------------
SortingTutorialController opens the existing success panel after Stage 2 resolver
completion. ToolTipTutorial guards the panel and scene loads against duplicates.
The existing button loads Level1.

Development reset options
-------------------------
Use one of these scoped methods when retesting:

- Press the Restart Tutorial button on the completion panel.
- Use "Reset This Tutorial Completion" from SortingTutorialController's component
  context menu.
- Enable Force Tutorial In Editor on the TutorialManager scene GameObject.
- Use "Reset Tutorial Progress" from that TutorialManager component's context
  menu.

GameDataManager's full PlayerPrefs reset is intentionally separate and should be
used only when all player data must be erased.

Manual Play Mode validation sequence
------------------------------------
1. Reset sorting.initial completion and open TUTORIAL.
2. Confirm the Stage 1 reference Orange Box appears at (1,2).
3. Confirm three Orange x1 rail Boxes arrive and the first Hand starts.
4. Make an invalid drop. Verify the same step returns and progress does not change.
5. Make a valid drop in the suggested cell. Verify immediate acceptance without an
   extra click and wait for sorting before the next Hand.
6. On a later move, choose another Board-accepted cell. Verify the next target uses
   the actual placement/reference that survived resolution.
7. Finish Stage 1. Verify one Match/removal completes and Stage 2 starts once.
8. Before moving the Stage 2 left Box, try dragging the middle and right Boxes.
   Verify neither Box moves at all and the current Hand instruction remains.
9. Place the left Box and wait for resolution. Try the right Box before the middle
   Box; verify the right Box remains fixed and only the middle Box can move.
10. Place the middle Box, wait for resolution, then verify the right Box unlocks.
11. Finish Stage 2. Verify two Matches, empty Board, hidden Hand, and one success
   panel.
12. Double-click Start Level 1. Verify Level1 loads once.
13. Return through startup with completion stored. Verify LoadManager routes to
    Level1 rather than starting the one-time Tutorial again.
14. Restart the Tutorial from its button. Verify TUTORIAL loads and guidance has no
    duplicate callbacks.
15. In Level1 verify placement, sorting, rail replenishment, Hammer, and Swap.

Console expectation
-------------------
No Tutorial-related exception should appear. A deliberate missing reference or
impossible recipe should produce one clear warning and cancel the affected
Tutorial safely instead of freezing gameplay.
