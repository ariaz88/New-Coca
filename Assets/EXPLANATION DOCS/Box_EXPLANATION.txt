BOX.CS - DRAG LIFECYCLE SIGNALS
===============================

Phase 2 capacity helper
-----------------------
Box.DiscoverableCapacity lets the editor read the same capacity definition used
at runtime without entering Play Mode. It first counts explicitly assigned
sodaSlots; if that list is empty, it counts children named SodaPosition<number>.
BoardEditor uses this read-only value to prevent a level designer from adding
more initial Soda colors than the selected Box prefab can actually contain. The
runtime Capacity property remains based on the slots discovered by Box.Awake.

Purpose of this change
----------------------
Box already owns mouse drag input. The old implementation also called
HandAnimation and ToolTipTutorial directly. That mixed gameplay input with one
specific Tutorial and caused a rejected second click to appear to advance a valid
placement.

Box now reports drag facts. It no longer decides what those facts mean to a
Tutorial.

New events
----------
DragStarted is an Action<Box>. It is raised only after all drag-start validation
succeeds, the pointer is projected onto the drag plane, dragOffset is calculated,
and isDragging becomes true.

DropRejectedOrCancelled is an Action<Box>. It is raised when a drag that actually
started is rejected by Board or is cancelled because interaction becomes
unavailable.

These are instance events. SortingTutorialController subscribes only to Boxes in
the active stage, which avoids receiving input from unrelated objects.

Owner-scoped drag constraint
----------------------------
Stage 2 needs a stronger rule than a DragStarted event. DragStarted is a report
sent after Box has already accepted the pointer and set isDragging true. Rejecting
the Box from that event would be too late: the object could move for one frame and
then snap back. The requirement is stricter: an out-of-order Box must never begin
moving.

Box therefore has two private fields:

dragConstraintOwner
    The system that temporarily owns the rule. In this project the owner is the
    active SortingTutorialController instance.

dragConstraint
    A Func<Box, bool>. It receives the Box being clicked and returns true only
    when that Box may begin a drag.

TrySetDragConstraint(owner, constraint) installs the rule. It rejects null values
and refuses to replace a rule owned by another object. ClearDragConstraint(owner)
removes the rule only when the same owner asks. This mirrors Board's owner-scoped
placement constraint and prevents one feature from accidentally disabling another
feature's input rule.

Normal levels never install a drag constraint, so dragConstraint remains null and
their input behavior is unchanged.

OnMouseDown execution
---------------------
Existing Hammer and Swap checks still run first for Boxes already on the Board.
Rail dragging still stops for retired, already-dragged, or Board Boxes; a finished
game; a resolving Board; a missing Camera; or a pointer that cannot reach the drag
plane.

Before pointer capture, OnMouseDown evaluates the optional dragConstraint. When it
returns false, the method returns immediately. It does not save a new startPos,
create a drag plane, set isDragging, invoke DragStarted, move the Transform, or hide
the Tutorial Hand. This is why clicking the Stage 2 middle/right Box early produces
no movement at all.

Only after these checks does Box:

1. Save startPos.
2. Create the drag plane.
3. Calculate dragOffset.
4. Set isDragging true.
5. Enable temporary dragged-Box display priority.
6. Invoke DragStarted(this).

The Tutorial uses this event to hide guidance while the player is performing the
gesture. It does not mark progress here because a drag can still be cancelled.

OnMouseUp execution
-------------------
Box asks Board.TryPlaceBox to accept the current drop. There are two outcomes:

Valid drop:
    Board accepts the Box. Box does not call the Tutorial. Board's
    PlacementAccepted event is the authoritative success signal.

Invalid drop:
    Box returns to startPos and invokes DropRejectedOrCancelled(this). The sorting
    Tutorial keeps the same step and restarts the same Hand instruction.

This separation fixes the extra-click bug. A successful mouse-up advances through
Board.PlacementAccepted. A later invalid click cannot accidentally provide the
missing success transition.

CancelDrag execution
--------------------
CancelDrag records whether a drag was active before clearing isDragging. It
restores startPos and clears the highlighted Node. It raises the cancellation event
only when wasDragging is true, preventing false rejection notifications from
cleanup calls that did not represent a player drag.

Dragged Box display priority
----------------------------
EnableDraggedDisplayPriority collects every Renderer under the dragged Box,
including the Soda renderers. It saves each renderer's existing sorting order and
materials, temporarily assigns private DraggedBoxOverlay material copies, and
applies the highest temporary sorting order.

DraggedBoxOverlay changes only the rendered clip-space depth of those temporary
material copies. The shared ToyGloss shader and all scene materials remain
untouched. The dragged Box therefore appears above Board Boxes while its body and
Sodas keep correct internal 3D occlusion. Its Transform, scale, drag plane, pointer
projection, collider, and Board placement reference never change.

OnMouseUp, CancelDrag, and OnDisable all call RestoreNormalDisplayPriority. The
saved materials and sorting order are restored for every renderer, covering
successful placement, rejected drops, returns to the rail, and object cleanup.

Removed coupling
----------------
The active Box implementation no longer calls:

- HandAnimation.instance.TryRestartAnimation after an invalid drop.
- ToolTipTutorial.instance.CompleteAnim after a valid drop.
- SpawnContoller.isTutorialState to decide Tutorial UI behavior.

Compatibility note
------------------
Older versions remain below #if false. Those references are intentionally inactive
and were not edited. BoardControllerV2 was also left unchanged as requested.

Subscription cleanup
--------------------
SortingTutorialController unsubscribes both Box events at stage transition,
completion, cancellation, disable, or scene unload. Destroying a Box also destroys
its event source, so matched Boxes cannot produce later callbacks. The same cleanup
also calls ClearDragConstraint(this), ensuring a Tutorial rule cannot leak into a
later stage or normal gameplay.

Persistent Tutorial highlight extension
---------------------------------------
The restored sorting Tutorial owns a persistent set of highlighted Nodes. While
Board.HasPlacementConstraint is true, OnMouseDrag records the Node under the mouse
but does not unhighlight, replace, or globally clear the controller-owned set.
OnMouseUp and CancelDrag likewise preserve those Nodes; the Tutorial controller is
their visual owner and clears them at authoritative lifecycle boundaries.

Mouse-up still asks Board.TryPlaceBox for the decision. An unhighlighted cell is
rejected by the registered constraint, so Box returns to its rail start position
and reports DropRejectedOrCancelled. When no placement constraint exists, normal
levels retain the original transient hovered-Node highlight behavior.
