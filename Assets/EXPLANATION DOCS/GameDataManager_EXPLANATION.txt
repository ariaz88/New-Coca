GAMEDATAMANAGER.CS - SAFE DEVELOPMENT RESET
===========================================

Problem in the previous Start method
------------------------------------
Start called ResetData unconditionally. ResetData uses PlayerPrefs.DeleteAll, so
every launch erased level, currency, tools, and any Tutorial completion state.

Implemented field
-----------------
resetDataOnStartForDevelopment is a private serialized bool shown under a
Development header. Its Tooltip warns that it deletes every PlayerPrefs key.

Implemented Start order
-----------------------
Start now does:

1. If resetDataOnStartForDevelopment is true, call ResetData.
2. Call LoadData.

The default and current scene value is false. Saved data therefore survives normal
launches. A developer can deliberately enable the field in the Inspector for a
full reset test.

ResetData remains public
------------------------
No API was removed. Existing development UI or scripts can still request a full
reset explicitly. The centralized Tutorial system does not use DeleteAll; it resets
only its own Tutorial.Completed.<id> key.

Why this is related to Tutorials
--------------------------------
TutorialManager writes sorting.initial completion through PlayerPrefs. Without
this gate, the completion store would appear broken because GameDataManager would
delete it on the next scene start.

Per-level runtime reset
-----------------------
GameDataManager survives scene changes, so runtime counters must not be treated as
permanent save data. BeginLevel now resets boxNum and coin whenever a gameplay
scene starts. Without this reset, reaching the win target once would leave boxNum
at or above the target in every later scene.

BeginLevel optionally receives the logical number parsed from the active scene
name. For example, Level6 passes 6. SetLevel then repairs the PlayerPrefs Level
value to 6. This prevents an earlier double click or failed scene load from leaving
saved progress at an impossible Level7 or Level8 while Level6 is active.

SetLevel versus IncrementLevel
------------------------------
IncrementLevel remains available for compatibility, but the authoritative
WinPanel flow no longer increments blindly. It calculates the next scene first,
checks that Unity can load it, and calls SetLevel only for a real configured
Level scene. The final level therefore cannot save an invalid future number.

Persistent values such as gems, TotalCoins, tools, and Tutorial completion are not
cleared by BeginLevel.
